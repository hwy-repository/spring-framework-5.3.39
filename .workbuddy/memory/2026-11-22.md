## 排查 Spring Framework 5.3.39 本地运行失败

工作区：`C:/software/spring/spring-framework-5.3.39`（Gradle 构建，用户新增了 `spring-debug` 模块用于调试源码）。

### 复现到的三处独立故障

1. **JDK 版本过旧（主因，源码编译失败）**
   - 环境 `JAVA_HOME=C:\Program Files\Java\jdk1.8.0_131`（2017 年的 8u131）。
   - `spring-core` 的 `org.springframework.core.metrics.jfr.*` 使用 `jdk.jfr.*` 注解；JFR 在 JDK 8u262+ 才回移植进 8，8u131 没有 → `找不到符号 类 Label/Description/Category/Event`，`:spring-core:compileJava` 失败。
   - 仓库 `.sdkmanrc` 指定 `java=8.0.382-librca`，印证需较新 JDK8。
   - 实测：用 `C:\Users\he875\.jdks\corretto-1.8.0_482` 设 JAVA_HOME 后，`:spring-core` / `:spring-beans` / `:spring-context` 全部编译成功。
   - 注意：用 JDK 11 会换成另一种失败——`-Werror` + `isAccessible()` 弃用警告（`buildSrc/.../CompilerConventionsPlugin.java` 全局开了 `-Xlint:deprecation -Werror`）。所以要用 JDK8u262+，不要用 11。

2. **`spring-debug` 未注册进 Gradle**
   - `settings.gradle` 没有 `include "spring-debug"` → 执行 `:spring-debug:compileJava` 报 `Project 'spring-debug' not found in root project 'spring'`。
   - 且根 `build.gradle` 设置 `project.buildFileName = "${project.name}.gradle"`，故需 `spring-debug/spring-debug.gradle`；该模块名以 `spring-` 开头会自动套用 `gradle/spring-module.gradle` 的完整约定。

3. **`spring-debug/pom.xml` 是坏的且不该存在**
   - 这是个 Gradle 工程；`.gitignore` 第 17 行忽略 `pom.xml`。
   - pom 里有个空的 `<dependency>`（groupId/artifactId/version 全空）→ Maven 直接解析失败。
   - pom 设 `source/target=11`，与 JDK8 冲突。
   - IDEA `.idea/misc.xml` 把它当 Maven 项目导入（`MavenProjectsManager`），与 Gradle 导入冲突。
   - 另外 IDEA 配置不一致：`gradle.xml` gradleJvm=1.8、`misc.xml` 项目 SDK=1.8、`workspace.xml` 里 `jdk.selected.JAVA_MODULE=11`。

### 修复方向
- JAVA_HOME/IDEA Gradle JVM 指向 JDK 8u262+（本机已装 Corretto 8u482）。
- settings.gradle 加 `include "spring-debug"`，补 `spring-debug/spring-debug.gradle` 并声明对 `spring-core`/`spring-beans`/`spring-context` 的依赖。
- 删除 pom.xml，统一走 Gradle；IDEA 里刷新 Gradle 项目并重新同步 JDK。

### 备注
- `https://ge.spring.io/cache/...` 返回 403 只是远程构建缓存连不上，会自动降级，不是失败原因。
- `settings.gradle` 已加阿里云 plugin 镜像、`gradle-wrapper.properties` 已改阿里云 distribution 镜像，这两处改动本身没问题。
